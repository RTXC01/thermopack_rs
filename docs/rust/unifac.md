# UNIFAC mixing rule

This module implements the UNIFAC activity coefficient model of the checked-in
ThermoPack fork, including the Flory-Huggins and Staverman-Guggenheim
combinatorial terms, and connects it to the cubic equation of state as a
mixing rule.

## Source scope

| Original routine | Rust |
| --- | --- |
| `src/unifac.f90:init_unifac` | `unifac::Unifac::new` |
| `src/unifac.f90:GeUNIFAC` | `unifac::Unifac::excess_gibbs` (residual part) |
| `src/unifac.f90:GeFloryHuggins` | `unifac::Unifac::flory_huggins` |
| `src/unifac.f90:GeStavermanGuggenheim` | `unifac::Unifac::staverman_guggenheim` |
| `src/unifac.f90:Ge_UNIFAC_GH_SG` | `unifac::Unifac::excess_gibbs` (combined) |
| `src/unifacdata.f90` | `unifac_data` (generated) |
| `src/excess_gibbs.f90:gExcess` | `excess_gibbs::excess_gibbs_cubic_mix` |

The database is generated by `tools/rust_port/generate_unifac_data.py` from
`src/unifacdata.f90`: 117 sub-groups with their main-group assignment, Rk and
Qk parameters, 20 component-to-group mappings and 1603 main-group interaction
records. The generated module keeps the source order, so the first-match
behaviour of the source lookup is preserved.

## Model

The model evaluates the excess Gibbs energy and its analytical composition and
temperature derivatives exactly as the original does:

* the residual UNIFAC part with the group activity coefficients
  $\lambda_k$ and the component group activity coefficients $\lambda_{ik}$,
* the Flory-Huggins combinatorial term,
* the Staverman-Guggenheim combinatorial term with $z/2 = 5$,
* the first and second composition derivatives and the mixed and second
  temperature derivatives.

The mixing-rule label selects the combinatorial terms, matching the original
`init_unifac`:

| Label | Flory-Huggins | Staverman-Guggenheim |
| --- | --- | --- |
| `UNIFAC` | yes | yes |
| `UMR` | no | yes |
| `VTPR` | no | no |

The original passes the composition to the model as **mole fractions**. The
mixing rule layer of the fork works with mole fractions throughout
(`cbCalcAmix` receives `zcomp` and forwards it to `ExcessGibbsMix`), so the
native model uses mole fractions as well and reports molar quantities.

## Cubic integration

`excess_gibbs::excess_gibbs_cubic_mix` dispatches to the UNIFAC kernel for
`MixingRule::Unifac` and to the Huron-Vidal/NRTL kernels otherwise. The
limiting constant follows the original:

* UNIFAC uses the zero-pressure limit `getZeroLimitC`: 0.55 for van der Waals,
  0.593 for SRK and 0.53087 for Peng-Robinson.
* The Huron-Vidal and NRTL models use the infinite-pressure limit
  `getInfinitLimitC`: 1 for van der Waals, $\ln 2$ for SRK and
  $-\ln(\sqrt{2}-1)/\sqrt{2}$ for Peng-Robinson.

The original selects the zero-pressure limit only for the UNIFAC mixing rule;
the previous native port used the infinite-pressure limit for van der Waals as
well, which the source does not.

## Units

The original reports energies per kilomole: its gas constant is
`1000.0*Rgas_default` and the comment on `kRgas` reads `J/kmol/K`. The native
crate works per mole with `R = 8.31446261815324 J/(mol K)`. The unit-level
fixtures therefore store the source values and scale the native values by 1000
for the comparison. The cubic integration is unaffected because the native
`a`, `b` and the excess Gibbs energy share the molar convention.

## Source limitations reproduced

* **Component list.** The original UNIFAC database holds 20 components. A
  component outside that list makes the original terminate. The native model
  returns an error instead.
* **Identifier mismatch.** The database spells toluene `TOLUENE` while the
  equation of state uses `TOLU`, so the original terminates for mixtures with
  toluene. The native model reports the same missing component.
* **Missing interaction parameters.** 26 main-group pairs occur twice in the
  source table with different values; the source returns the first match and
  the generated module keeps that order. Two directed pairs of the main groups
  that the 20 components activate are absent from the table; the source prints
  a message and uses zero parameters, and the native model uses zeros as well.
  The acetone/methane pair reaches the missing pair (9, 57).
* **Duplicated interaction pairs.** The first record wins, exactly as in the
  source scan.

## Validation

`tools/rust_port/validate_unifac.py` compares the native model against the
exact-source library through a reference probe that installs the requested
component list in the source globals, calls `init_unifac` and the source
excess Gibbs routine, and restores the globals afterwards.

* 1540 cases: 20 pure components at three temperatures and three labels, all
  190 binary pairs at three compositions for `UNIFAC` and at two compositions
  for `UMR` and `VTPR`, and five ternary mixtures at two temperatures and
  three labels.
* All 1540 cases match within a relative tolerance of 2e-10 with
  quantity-specific absolute tolerances. The excess Gibbs energy, both
  temperature derivatives, the composition derivatives, the mixed derivative
  and the second composition derivatives are compared.

`tools/rust_port/validate_unifac_cubic.py` compares the mixing rule inside the
cubic equation of state: 288 cases over PR and SRK, 16 mixtures and nine
states. 270 cases match, 18 terminate in the source because of the toluene
identifier, and the worst scaled errors are 1.5e-11 for the pressure and
2.4e-12 for the fugacity coefficients.

The committed fixtures are `tests/fixtures/unifac.csv`,
`tests/fixtures/unifac_status.csv`, `tests/fixtures/unifac_cubic.csv` and
`tests/fixtures/unifac_cubic_status.csv`; the tests are `tests/unifac.rs` and
`tests/unifac_cubic.rs`.

## Remaining scope

* The UMR and VTPR labels are available on the model but not yet selectable as
  cubic mixing rules; the original reaches them through the VTPR and UMR
  model initializers.
* The original does not use the binary interaction parameters of the UNIFAC
  mixing rule; the native model does not either.
* The `UNIFAC` and `UMR` labels use the Staverman-Guggenheim term, which needs
  a positive surface area parameter for every component. The `C1` sub-group of
  the source table has `Qk = 0`; no component of the supported list uses it,
  so the term stays finite.
